# 📋 Отчет монтажника

Веб-форма для заполнения ежедневных отчётов о монтажных работах. Данные уходят в Google Таблицу через Google Apps Script. Оптимизирована под телефон: крупные поля, тёмная тема, валидация на лету, зависимые поля.

---

## 🎯 Что делает

Монтажник открывает форму, заполняет данные о работе за день, жмёт «Отправить отчёт» — запись попадает в общую Google Таблицу компании. Один отчёт = одна или несколько строк (по числу израсходованных материалов).

## 🧩 Логика полей (зависимости)

Форма — не просто набор полей. Некоторые зависят друг от друга:

### Объект → Этаж → Помещение

- **Этаж** заблокирован, пока не выбран объект.
- Набор этажей зависит от объекта:
  - **Ларинская гимназия:** 1, 2, 3, Чердак, Нет
  - **ЖЕДЕПОМ:** Подвал, 1, 2, 3, Чердак, Нет
- **Помещение** заблокировано, пока не выбран этаж.
- Если этаж = **«Нет»** → помещение автоматически становится «Нет» и блокируется.
- Если помещения реально нет, но этаж обычный — монтажник вводит **0**.

### Тип работ → Система

- **Система** заблокирована, пока не выбран тип работ.
- Если тип работ = **«Монтаж»** или **«Демонтаж»** → система **активна и обязательна**.
- Если тип работ = **«Наставничество»** → система **не используется** (показывается подсказка).

### Система → Материалы

- **Кабель** фильтруется по системе:
  - `АПС/СОУЭ` → обе строки кабеля (х0,75 и х1)
  - `АПС` → только х0,75
  - `СОУЭ` → только х1
- Остальные материалы (кабель-канал, трубы) — одинаковы для всех систем.

### Названия систем

- **АПС/СОУЭ** — автоматическая пожарная сигнализация и система оповещения
- **АПС** — только автоматическая пожарная сигнализация
- **СОУЭ** — только система оповещения и управления эвакуацией

## 📤 Формат отправляемых данных

`POST` с `Content-Type: text/plain` (из-за `no-cors`), тело — JSON:

```json
{
  "object": "Ларинская гимназия",
  "date": "2026-09-26",
  "name": "Иван Иванов",
  "floor": "2",
  "room": "32, 105, 108",
  "room_none": false,
  "work": "Монтаж",
  "system": "АПС",
  "materials": [
    { "name": "Кабель КПСЭнг(A)FRHF 1x2x х0,75", "unit": "м", "qty": "12.5" },
    { "name": "Кабель-канал 40х25", "unit": "м", "qty": "3.2" },
    { "name": "Труба гофрированная d= 20 мм", "unit": "м", "qty": "25" }
  ]
}
```

| Поле | Тип | Обязательное | Примечание |
|------|-----|:---:|-----------|
| `object` | string | ✅ | `Ларинская гимназия` \| `ЖЕДЕПОМ` |
| `date` | string | ✅ | `YYYY-MM-DD`, не старше 7 дней |
| `name` | string | ✅ | ровно 2 слова, Имя + Фамилия |
| `floor` | string | ✅ | зависит от объекта |
| `room` | string | ✅ | цифры через запятую |
| `room_none` | boolean | — | `true` = помещения нет (этаж «Нет») |
| `work` | string | ✅ | `Монтаж` \| `Демонтаж` \| `Наставничество` |
| `system` | string | ✅ (условно) | обязательно для Монтаж / Демонтаж |
| `materials` | array | — | массив `{ name, unit, qty }`, пустые позиции не летят |

## 📊 Схема Google Таблицы

Лист `Сентябрь` (имя настраивается в `Code.gs`).

| A | B | C | D | E | F | G | H | I | J | K |
|---|---|---|---|---|---|---|---|---|---|---|
| Объект | Дата | Имя фамилия | Этаж | Помещение | Тип работ | Система | Материал | Ед.изм. | Кол-во | timestamp |

**Один материал = одна строка.** Если в отчёте 3 материала — в таблицу упадёт 3 строки, где A–G дублируются, а H–J разные. Если материалов нет — одна строка с пустыми H, I, J.

## ⚙️ Настройка бэкенда (Google Apps Script)

### Шаг 1. Создать таблицу

Лист с именем **`Сентябрь`** (или как у тебя) и заголовками A–K как в схеме выше.

Второй лист — **`Отклонённые`** — создаётся автоматически при первом отклонённом запросе.

### Шаг 2. Открыть Apps Script

В таблице: **Расширения → Apps Script**.

### Шаг 3. Вставить код

Полный `Code.gs` см. в репозитории или в истории переписки. Ключевое:

```javascript
const SHEET_NAME = 'Сентябрь';
const ALLOWED = {
  object: ['Ларинская гимназия', 'ЖЕДЕПОМ'],
  work:   ['Монтаж', 'Демонтаж', 'Наставничество'],
  system: ['АПС/СОУЭ', 'АПС', 'СОУЭ'],
  floor: {
    'Ларинская гимназия': ['1', '2', '3', 'Чердак', 'Нет'],
    'ЖЕДЕПОМ':            ['Подвал', '1', '2', '3', 'Чердак', 'Нет']
  }
};
```

### Шаг 4. Развернуть

**«Начать развёртывание» → «Управление развёртываниями» → ✏️ → «Новая версия» → «Развернуть»**.

- Запуск от имени: **Я**
- Доступ: **Все**

Скопируй URL и вставь в `script.js`:

```javascript
const API_URL = 'https://script.google.com/macros/s/.../exec';
```

## ⚠️ ВАЖНО: как обновлять Apps Script

Google **отдаёт старую версию скрипта** всем, кто стучится по URL, пока ты явно не опубликуешь новую. Сохранение (`Ctrl+S`) этого **не делает**.

**После каждой правки `Code.gs`:**

1. `Ctrl+S` — сохранить.
2. **«Начать развёртывание» → «Управление развёртываниями»**.
3. У текущего развёртывания — **карандаш ✏️**.
4. Поле **«Версия»** → выбрать **«Новая версия»**.
5. **«Развернуть»**.

**URL не меняется**, ничего в GitHub править не надо.

> 🔑 **Запомни:** поменял код в Apps Script — сразу переопубликуй развёртывание. Иначе будешь думать «я поменял, а не работает».

## 🧾 Материалы — как дополнять список

Список материалов живёт в `script.js` в константе `MATERIALS`:

```javascript
const MATERIALS = [
  {
    id: 'cable',
    label: 'Кабель КПСЭнг(A)FRHF 1x2x',
    unit: 'м',
    variants: [
      { id: 'cable_075', label: 'х0,75', systems: ['АПС/СОУЭ', 'АПС'] },
      { id: 'cable_1',   label: 'х1',    systems: ['АПС/СОУЭ', 'СОУЭ'] }
    ]
  },
  {
    id: 'channel',
    label: 'Кабель-канал',
    unit: 'м',
    variants: [
      { id: 'channel_40x25', label: '40х25', primary: true },
      { id: 'channel_25x16', label: '25х16' }
    ]
  },
  // ...
];
```

**Поля:**

| Поле | Что означает |
|------|-------------|
| `id` | уникальный, латиницей. Не менять после релиза |
| `label` | как материал показывается монтажнику |
| `unit` | единица измерения (`м`, `шт`, `кг`…) |
| `variants[].label` | что показывается в капсуле (например `40х25`) |
| `variants[].primary` | `true` — вариант выделяется синим (основной) |
| `variants[].systems` | массив систем, где виден вариант. Если не указан — виден всегда |

**Каждый вариант = отдельная строка в форме и отдельная строка в таблице.**

## 🛡️ Защита (на стороне Apps Script)

Форма отправляет данные через `no-cors`, поэтому клиент **не знает**, принял ли сервер данные. Вся защита — на стороне `doPost`:

| Угроза | Как отбивается |
|--------|----------------|
| Пустой / битый JSON | `try/catch` на парсинге |
| Пропущенные обязательные поля | Валидация `name`, `object`, `date`, `work` |
| Подделка имени | Регексп — ровно 2 слова |
| Левое значение объекта / этажа / работы / системы | Whitelist `ALLOWED` |
| Дата «из будущего» или «из 2010 года» | Только ±30 дней от сегодня |
| Гигантские строки | `sanitize()` режет по `MAX_*_LEN` |
| Спам одинаковым запросом | Антидубликат в течение 2 минут |
| Флуд с одного имени | Не более 5 отчётов в час |
| Массовая заливка | Глобальный лимит 500 записей в сутки |
| Ошибка в основном листе | Логирование отклонённых в отдельный лист |

**Система проверяется на сервере дважды:**
- Обязательна, если `work = Монтаж` или `Демонтаж`.
- Не нужна при `Наставничество`, но если есть — должна быть из whitelist.

## 🐛 Известные ограничения

- `fetch` работает с `mode: 'no-cors'` → **ответ сервера недоступен**, UI всегда показывает «✅ Отчет отправлен», даже если Apps Script упал.
- Нет офлайн-режима (PWA не настроен).
- Нет редактирования отправленных отчётов — только добавление.
- Определить IP в Apps Script нельзя (колонка `ip_hint` в листе «Отклонённые» всегда пустая).
- Точное время отправки — по времени сервера Google, не по времени устройства монтажника.
